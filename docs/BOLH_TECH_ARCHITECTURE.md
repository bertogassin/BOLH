# BOLH — Техническая архитектура

Высоконагруженная платформа закрытых тендеров охранных услуг. Соответствует [ABSOLUTE_STANDARD.md](../ABSOLUTE_STANDARD.md).

---

## 1. Ядро системы (Core Domain)

Домен реализован на **Rust**: максимальная строгость типов, невалидные состояния невозможны.

### 1.1. Сущности и взаимодействие

| Сущность | Описание |
|----------|----------|
| **Money** | Value object: `Decimal` + `Currency` (не `f64`) |
| **License** | Тип лицензии, верификация, срок действия |
| **Client** | ID, репутация (скоринг по истории) |
| **Guard** | Лицензии, расписание, ставка, верификация |
| **Agency** | Название, верификация, охранники, комиссия |
| **Order** | Заказ клиента: требования, бюджет, статус, видимость. **Цена заказа не видна никому, кроме алгоритма** (`actual_price: Option<Money>`) |
| **Bid** | Предложение от охранника/агентства: условия, цена, срок. **Не привязан к конкретному заказу** |
| **Match** | Результат алгоритма: order + bid + guard, итоговая цена, статус (Created → AcceptedByGuard → InProgress → Completed) |

### 1.2. Бизнес-правила (инварианты)

- Создание заказа: бюджет не ниже минимальной ставки.
- Клиент не видит цены участников; клиенту отдаётся только `OrderView` (id, requirements, status).
- Совпадение Bid и Order: алгоритм проверяет совместимость требований (локация, время, лицензии), вхождение цены в бюджет, репутацию. Участники не знают друг о друге.

Код домена: крейт **`bolh-domain`** в репозитории.

## 2. Технологический стек

### 2.1. Бэкенд

| Компонент | Технология | Обоснование |
|-----------|------------|-------------|
| Core бизнес-логика | **Rust** | Производительность, безопасность памяти, нет GC. Алгоритм подбора — микросекунды |
| API слой | **Go** | Сетевой I/O, конкурентность, скорость разработки |
| Высоконагруженные сервисы | Rust / Go | Matching Engine — обязательно Rust |
| БД | **PostgreSQL + Citus** | Реляционная модель, шардинг |
| Кэш | **Redis (кластер)** | Горячие данные |
| Очереди | **Kafka** | Надёжная доставка, партиционирование |
| Поиск | **Elasticsearch** | Сложный поиск по требованиям |
| Документы | **MinIO (S3)** | Сканы лицензий, паспортов |

### 2.2. Мобильные приложения

| Платформа | Стек | Обоснование |
|-----------|-----|-------------|
| iOS | **Swift + SwiftUI** | Нативная производительность, биометрия, 60/120 FPS |
| Android | **Kotlin + Jetpack Compose** | Нативная производительность, Material Design |

Кроссплатформа не используется: нативный код быстрее, лучше анимации, безопасность (биометрия, ключи), меньший размер приложения.

### 2.3. Веб (админка и агентства)

| Компонент | Технология |
|-----------|------------|
| Фреймворк | Next.js (React) |
| Стили | TailwindCSS |
| Состояние | Zustand |
| Типизация | TypeScript |

## 3. Архитектура микросервисов

```
                                    [Kafka]
                                       |
[Client App (Swift)] ---> [API Gateway (Go)] ---> [User Service (Go)]
                                       |          [Order Service (Rust)]
[Guard App (Kotlin)] ---> [API Gateway (Go)] ---> [Bid Service (Rust)]
                                       |          [Matching Engine (Rust)] <-- ядро
[Agency Web (Next.js)] -> [API Gateway (Go)] ---> [Notification Service (Go)]
                                       |          [Payment Service (Rust)]
                                       |          [Document Service (Go)]
                                       |
                                 [PostgreSQL Cluster]
                                 [Redis Cluster]
                                 [MinIO Storage]
```

### 3.1. Matching Engine (Rust)

Критичный компонент. Индексы в памяти (DashMap, RTree для локации, BTreeMap для цен). При новом заказе: поиск кандидатов по индексам → приоритизация (свободные агенты выше агентств) → выбор лучшего (цена + репутация) → создание Match → публикация в Kafka.

## 4. Модель данных

См. [migrations/001_initial_schema.sql](../migrations/001_initial_schema.sql) — PostgreSQL с PostGIS для геопоиска, GIN для JSONB, составные индексы. Citus для шардирования при масштабировании.

---

## 5. Безопасность

- **Шифрование:** чувствительные поля (цены в bids) — на уровне приложения; ключи — HSM/Vault; TLS 1.3.
- **Аутентификация:** JWT (короткий TTL), refresh с ротацией, биометрия на мобильных.
- **Верификация документов:** интеграция с госсервисами, AI-проверка, видеозвонки.
- **Изоляция:** сервисы не имеют прямого доступа к чужим БД; API Gateway проверяет права; Matching Engine не возвращает цены в API.

---

## 6. Производительность

- **Кэш:** L1 in-memory (Rust: cached, Go: bigcache), L2 Redis, L3 БД.
- **Индексы:** PostGIS, GIN для JSONB, составные под частые запросы.
- **Шардирование:** по географии и по user_id; Citus.
