# Ядро платформы BOLH (Super App)

Общая основа для всех сервисов: Guardian, DRIVE, HOME, WORK, HEALTH и будущих вертикалей.

---

## 1. Единая аутентификация

- Один аккаунт на все сервисы (email/телефон + пароль, OAuth, при необходимости 2FA).
- Единый JWT/сессия; все приложения (веб, iOS, Android) обращаются к одному Auth/API Gateway.
- В BOLH уже: API Gateway (Guardian) с JWT; расширение — единый домен/шлюз для всех вертикалей.

---

## 2. Единый профиль

- Имя, фамилия, аватар, контакты, язык, тема (светлая/тёмная), часовой пояс.
- Один источник правды (User service / профиль в БД); все сервисы читают через API.
- В BOLH уже: профиль в Guardian (client-web, API); расширение — общий модуль профиля для DRIVE/HOME и т.д.

---

## 3. Единый кошелёк

- Баланс пользователя, пополнение, списание за заказы в любом сервисе (Guardian, DRIVE, HOME и т.д.).
- История операций по всем сервисам в одном месте.
- В BOLH: отдельный сервис Wallet или модуль в API Gateway; интеграция с платёжными провайдерами.

---

## 4. Единые уведомления

- Центр уведомлений: push, email, in-app; фильтр по сервису и типу.
- Один Notification service подписан на события из всех вертикалей (Kafka/очереди).
- В BOLH уже: notification-service (заглушки); расширение — шаблоны и каналы для каждого сервиса.

---

## 5. Единые настройки

- Язык (43 языка), тема, уведомления (вкл/выкл по типам), приватность.
- Хранятся в профиле пользователя; все приложения читают одни и те же настройки.

---

## 6. Единый чат

- Чат с поддержкой и чаты между пользователями (клиент–охранник, заказчик–мастер и т.д.).
- Один Chat service или модуль; идентификация по user_id и контексту заказа/поездки/задачи.
- В BOLH: пока в спецификации; реализация после стабилизации Guardian.

---

## 7. Единая карта

- Геолокация для заказов охраны, поездок (DRIVE), выездов мастеров (HOME), курьеров (WORK).
- Один слой карты в приложении; разные маркеры/слои в зависимости от активного сервиса.
- В BOLH уже: координаты в заказах Guardian; расширение — общий Map SDK/компонент.

---

## 8. Единая аналитика

- События поведения (логин, экраны, действия) в одном формате; единый pipeline (например, Kafka → хранилище).
- Дашборды по продукту и по сервисам; когорты и ретеншн считаются по общему user_id.

---

## Принцип добавления нового сервиса

- Новый сервис (например DRIVE) использует: тот же аккаунт (Auth), тот же профиль, тот же кошелёк, те же уведомления и настройки.
- Специфично для сервиса: свои сущности (поездка, водитель), свои роли, свой UX и API; события (TripCreated и т.д.) летят в общую шину для уведомлений и аналитики.

Детальные спеки сервисов: см. `guardian/docs/services/` (DRIVE_SPEC, HOME_SPEC, WORK_SPEC, HEALTH_SPEC) по мере их создания.
